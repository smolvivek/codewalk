Module 1 · The shape of the whole thing

One wire service, many local editions

Before any code: what talks to what, and why it's split the way it is.

This isn't a website with routes and a database. It's a small pipeline with a hard line drawn through the middle of it: one scriptgenerate-feed.js — runs on a schedule, needs API keys, writes the public feed files. does all the expensive, credentialed fetching once a day, centrally. Every user's local script reads the output of that — plain public JSON — needing no keys of its own.

Five modules below trace that line left to right, one concept at a time. Each one names the shape of the idea — a boundary, a ledger, a gate, a lookup chain, a pipeline — so you can recognize the same shape next time you meet it somewhere else, in a different codebase entirely.

Module 2 · Shape: Boundary

The wire service never touches your machine

src/generate-feed.js vs scripts/prepare-digest.js

domain metaphor Think of generate-feed.js as the wire service — the one newsroom with a press passAn API key: a credential that proves you're allowed to call a service, rate-limited and tied to one account. that calls reporters directly (the X API, podcast RSS feeds) and files one story a day. Every subscribing local paper (your own machine, running prepare-digest.js) just pulls the wire copy off a public feed — no press pass required, because the wire service already did the credentialed part.
scripts/generate-feed.jsconst xBearerToken = process.env.X_BEARER_TOKEN; const pod2txtKey = process.env.POD2TXT_API_KEY; if (runTweets && !xBearerToken) { console.error("X_BEARER_TOKEN not set"); process.exit(1); }
This is the only place in the whole project that checks for an API key. It runs once a day, centrally, as a GitHub Actions job — not on any individual user's machine. If the key is missing, it refuses to run at all rather than produce a half-empty feed.
scripts/prepare-digest.jsconst FEED_X_URL = 'https://raw.githubusercontent.com/zarazhangrui/' + 'follow-builders/main/feed-x.json'; const [feedX, feedPodcasts, feedBlogs] = await Promise.all([ fetchJSON(FEED_X_URL), ... ]);
This runs on every user's own machine, with zero credentials. It just fetches three public JSON files off GitHub — the output the wire service already published. That's the whole reason a boundary like this exists: the expensive, rate-limited, credentialed work happens once, centrally; the cheap part happens everywhere, for free.

Module 3 · Shape: Ledger

Nothing gets wired twice

state-feed.json

domain metaphor Every wire service keeps a circulation logAn append-only record used to reconstruct or check past state — here, which tweet/episode/article IDs have already gone out. of story IDs it has already transmitted, so the same story never gets sent to a paper twice. That log is state-feed.json: three maps — seen tweets, seen videos, seen articles — each entry just an ID pointing at the timestamp it was first seen.
scripts/generate-feed.jsfor (const t of allTweets) { if (state.seenTweets[t.id]) continue; // dedup if (newTweets.length >= MAX_TWEETS_PER_USER) break; newTweets.push({ id: t.id, ... }); state.seenTweets[t.id] = Date.now(); }
For every tweet the X API returns, the very first check is: is this ID already in the ledger? If so, skip it — it already went out in a previous run. New ones get added to the ledger the moment they're selected, before anything can go wrong downstream.

Module 4 · Shape: Gate

The editor never calls a source directly

The agent's instructions in SKILL.md, Content Delivery → Step 4

domain metaphor A wire editor at the local paper doesn't get to phone up a source and ask follow-up questions — they work only from the wire copy in front of them. If a fact isn't on the page, it doesn't go in the story. That's a deliberate gate, and it's the single most important design decision in this codebase: it's what stops the LLM from fabricatingHallucination — an LLM generating plausible-sounding content that wasn't actually in its source material. a quote, a launch, or a URL that doesn't exist.
SKILL.md**Your ONLY job is to remix the content from the JSON.** Do NOT fetch anything from the web, visit any URLs, or call any APIs. Everything is in the JSON. **ABSOLUTE RULES:** - NEVER invent or fabricate content. - Every piece of content MUST have its URL. No URL = do not include.
This isn't a suggestion, it's the gate itself: the agent is told, in plain language, that its whole job is downstream of a script that already did every network call. No URL attached to a claim means that claim doesn't make it into the digest — full stop, no exceptions written in.

Module 5 · Shape: Lookup chain

Your style notes beat the house style

prepare-digest.js, the prompt-loading loop

domain metaphor Three places to find today's style guide, checked in order: your own handwritten notes pinned above your desk (did you personalize it yourself?), the wire service's current style memo (fresh off GitHub), or the dusty backup copy that shipped with the newsroom's software in case the network's down. First one found wins.
scripts/prepare-digest.jsif (existsSync(userPath)) { prompts[key] = await readFile(userPath); continue; // 1. user's own copy } const remote = await fetchText(url); if (remote) { prompts[key] = remote; continue; // 2. latest from GitHub } if (existsSync(localPath)) { prompts[key] = await readFile(localPath); // 3. shipped fallback }
Three tries, in priority order, for each prompt file separately. A user who's customized one prompt (say, "make tweet summaries shorter") keeps that customization forever — central updates to the other, un-customized prompts still reach them normally.

Module 6 · Shape: Pipeline

Same story, three presses

scripts/deliver.js

domain metaphor One finished story, three different presses it can run through depending on how the reader wants it — the Telegram press, which has to cut long runs into 4,000-character platesTelegram's API rejects any single message over 4096 characters, so long digests get split and sent as several messages.; the email press, which doesn't; or just handing the galley proof straight to whoever's standing at the machine (stdout, the default).
scripts/deliver.jsconst MAX_LEN = 4000; while (remaining.length > 0) { if (remaining.length <= MAX_LEN) { chunks.push(remaining); break; } let splitAt = remaining.lastIndexOf('\n', MAX_LEN); if (splitAt < MAX_LEN * 0.5) splitAt = MAX_LEN; chunks.push(remaining.slice(0, splitAt)); remaining = remaining.slice(splitAt); }
It tries to split on a newline near the limit, so a chunk doesn't cut off mid-sentence — but if the nearest newline is too far back (less than half the max length), it gives up on finding a clean break and just cuts at the hard limit instead.
